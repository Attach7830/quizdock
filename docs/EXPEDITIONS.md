# QuizDock expeditions

This update extends the existing games, accounts, lists and reports. It keeps the six existing multiple-choice games and the separate typed Word Forge and Sketch Relay modes. Questions still use shuffled passes. The Adventure button opens optional maps and choices; question, answer and drawing controls keep the existing viewport layout.

A correct answer earns an adventure token (12 maximum). Spent tokens buy in-round actions. Adventure bonuses affect the round score. They do not change answer correctness, assignment requirements, active practice time, character-point award rates or candy eligibility. Saved discoveries arrive when a round finishes. Signed-in students in a linked class get a persistent expedition passport; nickname rooms keep their discoveries within that room.

## Public About page

`/about.html` welcomes visitors without an account. Scroll-linked previews use the real game scenes, planes and characters, with a dedicated drawing mural and interactive outfit previews. It makes no student-account or class API requests. Navigation and hero actions lead to actual game join and sign-in screens. Motion can be paused, follows system preferences, and stops when the preview is outside the viewport or the tab is hidden. The full introduction remains readable without JavaScript.

## Teaching and controls

Create a class-linked game as usual. Event intensity is in the host dialog and between-round controls. Between rounds, teachers can choose a specific word activity or drawing format, or leave automatic variety enabled. Students open Adventure from the compact game menu or answer-result shortcut. Stats, field guide, music, solo pause/end and animation controls remain in that menu. Leaderboards, the live joined-player list and the teacher’s class roster display each student’s character with their saved accessories. Class roster responses include only the owned appearance needed for this display.

The top-level Class island tab shows the campaign, construction, own passport, aquarium, hangar, collections and mural. Outfit presets are in Avatar wardrobe. In Solo study, Recovery quest uses missed typed answers; a correct answer retires one outstanding miss. Assignments always retain their full snapshot and categories. The assignment Word workshop uses the current practice lease and requires a checked typed answer for any grade progress.

Lists accept optional Hint, Example, Repair and Word Parts fields in the editor, JSON and CSV. CSV parts are separated by `|`. Parts must concatenate to the first accepted answer. Examples redact accepted answers before being sent as live clues. Sentence repair uses teacher-supplied text or a quoted correction prompt. Infinitive stem/ending labels require an infinitive prompt; other automatic chunks are called word pieces. Missing teacher content disables that clue or falls back to the standard forge.

## Persistence and compatibility

The existing Durable Objects and namespaces are unchanged. Old rooms and clients keep legacy mechanics unless `settings.engagement` is true. The new UI enables expeditions for new rounds. Round changes reset game resources, votes and loadouts, while retaining verified account identity, equipment, passport and hangar. Adventure actions use authenticated players, current round numbers, exact own revisions and bounded idempotency receipts. Invalid actions restore the whole room checkpoint.

Finished report delivery carries a server-authored expedition outcome. Per-user and per-class round receipts prevent duplicate progress, including outbox retries. Class ownership, current membership, account creation times, erasure tombstones, deleted reports and retention rules gate recording. Only the student’s own best score history appears in their game state. Class murals omit account identifiers in client responses.

Class backups include new class progression. Personal exports include the student’s profile, receipts and their own gallery contributions. Student erasure removes progression and associated class art, purges active-room state, and blocks old reports and backups from reviving erased work. Global wardrobe presets remain account data and follow existing full-account erasure rules. Production data is never used in test fixtures.

## Validation

`npm run verify` checks JavaScript syntax, tracked credential patterns and server tests. `npm run test:browser` runs the existing UI suites plus an expedition suite against isolated fake accounts over local TLS. Coverage includes each mode’s mechanics, token/idempotency/round guards, metadata round trips, drawing privacy and constraints, recovery and assignment invariants, persistence, erasure, class views, presets and desktop/phone layouts. The Worker is bundled separately with `wrangler deploy --dry-run` before publishing.

Deployment status is recorded in the release PR and the delivery report; source tests alone do not establish a live deployment or a real student’s authenticated production workflow.
