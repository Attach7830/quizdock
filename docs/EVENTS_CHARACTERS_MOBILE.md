# Event, character and mobile answer update

Release identifier: `classroom-release-2026-11-14.5` (package 0.6.0). Base inspected: main `54230c8489881a398f148adfac0764c8294d6370`, including the authorized-teacher Google sign-in release. All other remote feature branches were already ancestors of main; no unfinished divergent implementation was discarded.

Special events now produce a body-mounted, one-shot announcement: a large italic title such as *Aegis bloom!* and the actual awarded result, such as “25 health restored” or “4 health restored” when health is capped. Combined health/score rewards appear together. The browser uses server-issued event values; event cadence, payouts, damage and grading are unchanged. The announcement lasts 3.2 seconds and can be dismissed with its button or Escape. Score updates cannot restart it. Initial/reconnected snapshots establish a baseline, and questions, pauses, round changes and hidden tabs cancel active announcements. Motion-off and reduced-motion preferences use a static announcement; closely spaced events suppress repeated impact animations. It does not steal focus or change scrolling.

Game-result canvases are larger, with responsive portrait framing, richer atmosphere and full-scene reward rays, rings and particles. Each of the existing 18 special effects remains distinct and is enlarged. Scene visibility, motion settings, hidden-tab suspension and contained canvas drawing remain available. Artwork and effects use local vector geometry with cached paths.

All eight existing characters receive original detailed silhouettes and accessories. Their IDs, prices and prior ownership remain. Five new cosmetics use the existing wallet: Stormwing Ace (180), Frostblade Knight (220), Nebula Mage (300), Sunforge Sentinel (350), Nightfall Kitsune (450). Shop SVG portraits and the game canvas share the same geometry. Purchases and equips continue through the existing serialized account service; this release adds no storage schema, migration, purchase endpoint or reward rules.

On phone/coarse-pointer question screens, the two-by-two answer grid has a minimum height of two-thirds of the visible viewport. A compact header and measured spacer place it in the lower two-thirds for short prompts. Sizing updates on viewport changes, fullscreen transitions and prompt-image loads. Long prompts/images and long answer text expand the document naturally instead of being clipped. Existing questions with fewer than four real choices keep those choices. Within-view room updates preserve scroll; deliberate question/result transitions reset the new view to the top.

Validation uses isolated fake accounts and storage. Node tests cover actual capped event amounts, all event currencies, safe/unique character geometry, preserved IDs/prices, concurrent duplicate purchases, affordability and existing ownership. Browser checks cover the real shop/wallet/equip flow, seven phone/tablet/landscape viewports plus a wide touch-device viewport, long-answer expansion, native Chromium fullscreen, announcement lifetime/cancellation/accessibility, and all 18 enlarged event renderings. Existing suites continue to cover Google identity, grade and confidence persistence, long-prompt scrolling, reconnect, same-room mode changes, role planes, result screens and complete synthesized music rendering. The independent teacher Google suite checks both sign-in entry points.

Commit, merge and Cloudflare deployment status are recorded separately in the PR/handoff after their checks complete. The public health endpoint identifies the live release. Automated desktop Chromium viewports and native fullscreen checks do not establish physical iOS/Android browser behavior or an authenticated production Google classroom session; use `LIVE_ACCEPTANCE.md` for those checks.
